DX / Status

Direct RF DX detection, all-time records and independent station reports

Open DX / Status in the sidebar. DX detection does not require APRS-IS, and reports do not require a beacon entry. Existing position beacons keep their own schedule.

DX detection

A qualifying packet must contain the source station's position, be received via RF, have no used relay hop, and not be an Internet or third-party packet, object, item, or 0,0 position. Distance and initial true bearing are measured from the configured station position at reception. Configure GPS, a fixed GPS source or an enabled fixed-position beacon first. Positions are never borrowed from APRS-IS.

  • Minimum distance: ignore DX receptions at or below this distance, in kilometres.
  • Window: retain qualifying receptions for this many minutes (default 60). A mobile moving closer does not erase an earlier farther reception before its window expires. Equal distances select the newest reception.
  • Ignore stations: exact callsign-SSID values separated by spaces or commas. Ignoring a station for DX does not remove it from RF counters.
  • Max ever: the largest distance recorded per channel, saved across restarts. Clear max ever starts a new record history; it does not clear current window receptions.

Modem, KISS TNC and channel-bound Native TNC2 receptions qualify. Unassigned TNC2 and RXT telemetry streams are excluded. Remote receivers must represent the configured station location for distances to be meaningful.

Station reports

There are two independent opt-in reports, both with a default interval of 60 minutes. Select their receive channel, destination (RF, APRS-IS or both), RF path and whether to include DX, then save. Neither report transmits a position.

ReportExample information field
Status>Graywolf DX=F5ZQB-10(139km@136deg)
iGate capabilities<IGATE,MSG_CNT=26,LOC_CNT=5,DIR_CNT=5,RF_CNT=29,DX=F5ZQB-10(139km@136deg)

When no DX qualifies, capability reports still carry counters, and status reports carry their configured text. An empty status with no DX is skipped. “Send status now” and “Send capabilities now” use the saved settings and normal TX authorization/dedup rules. APRS-IS output requires the iGate to be connected; saving these settings does not enable it automatically.

Receiver DX from RXT measurements

For each receiver identified in the configured JSON streams or their measured RXT hops, the map popup and pinned window display a Receiver DX · RXT card. Graywolf calculates distance and true bearing from that receiver's known position to the actual transmitter of each measured radio link. A relay reception counts the relay as the transmitter, not the original packet source. Both endpoint positions must be known; unresolved observations remain pending until positions arrive. Position data locates endpoints, but never establishes reception by itself.

The card shows the farthest qualifying link in the configured DX window, its reception time, RSSI, SNR and frequency offset, plus the number of distinct transmitters observed at this receiver in the last 30 minutes. Minimum distance, window and ignored-station filters follow DX / Status settings. Earlier farther observations remain valid until their own expiry. These receiver calculations are passive and do not transmit an APRS report.

Remote RXT observations may cover only part of a receiver's traffic. The direct-station count is therefore an observed count, not a firmware-wide total. No MSG_CNT, LOC_CNT or RF_CNT is inferred. The current per-receiver window is held in memory and starts empty after restart. This calculation consumes versioned JSON streams; legacy /rxt.json polling remains an overlay source only.

Station popups on the live map

Stations advertising <IGATE,... capability bulletins get an iGate report card in their map popup and pinned window. It displays the reported MSG_CNT, LOC_CNT, DIR_CNT and RF_CNT values when present, plus DX and the bulletin reception date/time. These are values announced by that remote station, not measurements by your Graywolf receiver; their definitions and counting windows depend on the sender.

A station must have a known position to appear on the map. A bulletin received before its position is retained until the position arrives. Later position packets do not erase the report; a new bulletin without DX removes the previous DX. Reports survive restarts when station-history persistence is enabled. Existing historical raw packets are not backfilled; wait for the next bulletin after installing.

Station popups and pinned windows explicitly show “DX inconnu — aucune réception documentée” when no receiver observations or advertised DX are available. A capability bulletin without a DX instead shows “DX inconnu — aucun DX annoncé”. Neither message means a measured zero-distance DX. Objects and items do not get this station-only indication.

Immediate notifications

Optional immediate DX status notifications require status reports and Include DX. The trigger distance controls when a new DX may notify. Repeated notifications for the same station obey the minimum interval; a different, farther station can trigger immediately. Window expiry alone never transmits a report. Notifications are disabled by default; no DX-cluster packet generation is implemented.

Queries

A directed, unnumbered ?DX message to the configured station callsign returns an unnumbered one-shot DX reply. A directed ?IGATE? returns capabilities. Replies follow the incoming transport: RF queries reply on their receive channel, APRS-IS queries reply on APRS-IS. Queries do not create ACKs or reliable-message retries. Replies are throttled to one per sender per 30 seconds; generic broadcast queries are not implemented.

Counter meanings

TokenMeaning
MSG_CNTAPRS-IS message packets successfully handed to this channel's RF output since process startup. Queue admission and failed sends do not count. A successful handoff is not confirmation of RF delivery.
LOC_CNTDistinct source callsigns heard directly within 30 minutes, following Graywolf's current direct-only message reachability rule. Equals DIR_CNT. APRSISCE/32 allows relayed local stations under its own policy; this counter can therefore differ.
DIR_CNTDistinct source callsigns heard directly within 30 minutes, including positionless packets. A relayed copy does not erase a still-recent direct reception.
RF_CNTDistinct source callsigns received on RF within 30 minutes, including relayed sources. Objects and third-party packets count the outer RF source, not an object name or inner Internet source.

Heard counts and the current DX window restart empty. Max-ever records and settings persist. The initial local test build's dedicated DX beacon entries are transferred to the station-report settings once and retained disabled; new DX beacon entries are rejected.

Reference and limits

The detection/settings model and distinction between status and capabilities follow the APRSISCE/32 context help. The capability format is defined in APRS101 chapter 15. Graywolf implements the features described here; it is not a complete APRSISCE/32 clone and does not claim equivalent PinPoint behavior.
