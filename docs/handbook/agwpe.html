AGWPE

AGW Packet Engine protocol interface for legacy software

The AGWPE (AGW Packet Engine) interface provides compatibility with Windows packet radio software that speaks the AGW protocol. This is a single-instance TCP server that supports multiple simultaneous clients and up to four radio ports.

AGWPE interface configuration with listen address and per-port callsigns

Settings

FieldDefaultDescription
enabled false Enable the AGWPE listener
listen_addr 0.0.0.0:8000 TCP listen address
callsigns — Comma-separated callsigns, one per AGW port (max 4)

Use Graywolf as an AGWPE client

To keep an existing AGW Packet Engine installation in charge of the radio, open the KISS page (KISS / AGWPE Interfaces) and add a TCP Client with protocol AGWPE (APRS client). Enter its host (127.0.0.1 on the same computer), TCP port (normally 8000), and radio port as numbered in AGWPE (1 through 16). Assign a Graywolf channel with external TNC backing. Leave connected-mode passthrough off.

Enable the TCP/IP application interface in AGWPE and permit connections from the Graywolf computer. This initial client does not send an AGWPE username/password login. Do not point it at Graywolf's own AGW listener.

One saved interface selects one remote radio port; add another interface and channel to use another port. Graywolf queries the server's port list, checks that the selected port exists, and subscribes to raw reception. Only packets from that radio port enter its channel. Emission uses the normal Graywolf transmission queue and its enable/disable controls. Enable “Allow digipeater/beacon/iGate to transmit” when transmission is wanted. Choose APRS mode on the channel.

Disconnects trigger automatic retry. The existing status and Reconnect controls apply. This client transports APRS UI frames; it does not expose AGWPE-managed connected packet sessions. The server documented below is a separate function and need not be enabled to use the client.

Validation: protocol fixtures and automated tests cover binary APRS RX/TX, radio-port filtering, discovery failures, cancellation and reconnect. On 12 November 2026, APRS reception and transmission were also validated against real AGW Packet Engine in a Windows 11 VirtualBox guest, using its LoopBack Port. An independent socket client injected F4MLV-14>APGRWO,RFONLY:>GW-AGW-RX-222142; Graywolf decoded it at 22:21:42 CET on channel 2. A temporary, disabled custom beacon was then sent manually through that channel with marker GW-AGW-TX-20261112. The independent client received its raw K frame from AGWPE, and the temporary beacon was deleted. The channel counters reached RX 2 / TX 1 (including loopback reception of the transmitted frame); no test packet was gated to APRS-IS. This validates the software transport, not audio, PTT or an over-the-air radio link.

For an off-air test, select a radio port whose advertised description actually identifies LoopBack Port. In the validated installation, AGWPE advertised Port 1 as LoopBack and Port 2 as ?>NOTHING IDLE. A successful TCP connection to an idle slot does not establish a usable loopback or radio path.

Port Mapping

Graywolf’s AGW server exposes up to four radio ports (numbered 0–3). Each port is mapped to a callsign specified in the callsigns field. The order determines the port number: 

callsigns: "N0CALL,N0CALL-5,N0CALL-10"
# Port 0 → N0CALL
# Port 1 → N0CALL-5
# Port 2 → N0CALL-10

Supported Frame Types

Graywolf implements the AGWPE protocol subset needed for packet radio operations:

  • Monitor frames — receive decoded AX.25 packets
  • Unproto frames — transmit UI (unnumbered information) packets
  • Raw frames — send and receive raw AX.25 data
  • Connected-mode sessions — call out to a remote station, with or without digipeaters, and exchange data over the link. Clients such as Paracon, AGWTerm and EasyTerm can use graywolf as their TNC for BBS and node access.

Connected Mode

Connected mode is outbound only. Your AGWPE client can raise a link to a remote station, but an incoming call from the air is not handed to AGWPE clients.

⚠

The channel your AGWPE port maps to must have its mode set to Packet or APRS + Packet on the Channels page. Channels are APRS-only by default, and an APRS-only channel refuses connected-mode calls. Your client will report the attempt as disconnected with the reason.

ⓘ

Port 8000 is the conventional AGWPE port. Most AGWPE-compatible software will default to this port.
